# 0.1.0 测试结果

日期：2026-11-11。所有公开输入和输出均为合成素材，不包含客户文稿、客户身份或生产认证信息。

## 实际执行

OpenClaw 2026.8.1，两个独立测试agent，均配置`deepseek/deepseek-flash`，仅允许read工具，无消息渠道绑定。每个题目、每个对照组使用新会话。基线无本skill；candidate安装本skill并显式调用。两组获得相同的合成样稿、旧模型猜测、作者已确认反馈和当前事实包。

| 检查 | 基线 | 新skill |
|---|---:|---:|
| 作者视角转写 | 通过 | 通过 |
| 新会话遵守当前提供的偏好 | 通过 | 通过 |
| 风格结论附可定位样稿证据 | 通过 | 通过 |
| 旧样稿事实不混入新稿 | 通过 | 通过 |
| 本次通知要求覆盖历史口播偏好 | 通过 | 通过 |
| 素材不足时保留缺口 | 通过 | 通过 |
| 不把第一人称要求改成代词配额 | 通过 | 通过 |
| 压缩论证并保留等待时间条件 | 通过 | 通过 |
| 合计：题目级客观检查 | **8/8** | **8/8** |
| 单次生成耗时中位数 | **6.14秒** | **14.59秒** |
| 观察到读取正确skill文件 | 0/8 | 8/8 |

**这个小样本没有证明新skill优于基线。** 基线已经得到结构清晰的上下文；新skill有额外的工具读取开销。计数检查、JSON检查和字数检查不能完整判断事实蕴含、逻辑、作者语感或实际朗读时长。

结果原文与逐项检查见[results.json](results.json)。每题每组仅一次，无固定随机种子、无统计显著性分析、无真人编辑盲评；顺序固定为基线后candidate，可能受缓存和运行状态影响。

## 有失败记录的触发测试

另用同一个合成题目，在不显式点名skill的新会话中检查自动发现：

1. 初版描述：正文通过客观检查，但**未观察到读取skill**。不能算skill触发成功。
2. 只修改description，补充“按我的风格写口播”“把新闻改成我的文案”等具体请求表述；新会话重测：**观察到读取skill，正文通过检查**，耗时13.35秒。

这是针对已见失败的定点修正，只有一次重测，不能据此宣称自动触发率。产品应显式路由关键skill，并核对实际读取轨迹。

主对照测试用的是初版description；正文指导不变。`results.json`分别记录测试时与发布时的SHA256，避免把修改后的文件冒充全部8组的原始测试版本。

## 持久化与新会话

本地标准库脚本的6项单元测试通过：跨账号读写拒绝、候选不自动生效、显式替换保留历史、新进程读取当前版本、过期写入拒绝、不同体裁/全局范围冲突拒绝。

另外在OpenClaw测试账号完成一次端到端检查：创建偏好v1，将招呼规则显式替换为v2；从磁盘重新编译上下文，只注入1条当前有效规则，再创建新会话调用skill。旧规则未进入上下文，输出遵守新偏好，且观察到读取skill，耗时5.60秒。这验证了本仓库参考工具的链路，不代表任何外部应用已经完成集成。

## 编辑抽查发现

候选风格提炼能指出“常用家人们”“所有稿件必须编号/提问”缺少依据，并为其余规则提供原文短摘录。但简单客观检查仍可能漏掉扩大表述，例如把“18户报名”写成“都是愿意拿出闲置物品的人”。真实验收应继续检查每个结论是否由材料支持。

后续应使用未参与改提示词的新题和真实编辑修改分钟数验证价值；不以这次通过率承诺“像本人90%”或流量增长。
